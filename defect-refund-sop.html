三、1688采购单 — 退款+退货流程

操作步骤

  1. 仓库扫码登记次品 → 拍照上传
  2. 点一键退货 → 弹窗按供应商分组 → 确认
  3. 系统同时做两件事：
    • 创建聚水潭采购退货订单（同供应商合并，~2分钟回写内部单号）
    • 打开1688后台退货页面
  4. 在1688后台提交退款申请（带图片凭证）
  5. 等卖家同意 → 在聚水潭退货订单打面单发货寄回
  6. 卖家确认收货 → 退款成功
⚠️ 两条线并行：聚水潭退货单（打面单发货）+ 1688退款（拿回货款），缺一不可。

状态流转

待处理 → 等待卖家同意 → 等待买家退货 → 等待卖家收货 → 退款成功(完成) ↓ 卖家拒绝(异常)

各节点时间

节点时间
一键退货 → 聚水潭订单创建~2分钟
等待卖家同意1-3天
买家退货（寄回）打面单后1-3天
卖家收货 → 退款成功确认后即时

四、非1688采购单 — 退货流程

操作步骤

  1. 仓库扫码登记次品 → 拍照上传
  2. 点一键退货 → 弹窗按供应商分组 → 确认
  3. 系统自动创建聚水潭采购退货订单（~2分钟）
  4. 去聚水潭"外贸采购退货"店铺打面单发货

状态流转

待处理 → ⏳创建中 → ✅已下单(内部单号) = 完成 ↓ ↓ 未匹配 退货失败

五、一键退货

  1. 点"一键退货"按钮
  2. 弹窗列出待退货记录，按供应商分组（仅显示供应商名+数量）
  3. 🔵1688 / 🟡非1688 标签区分来源
  4. 勾选确认 → 提交
  5. cron ~2分钟内：按供应商合并 → 创建聚水潭退货订单 → 回写内部单号

范围：所有未建聚水潭退货单的记录（含1688退款中但未建单的）

六、重新匹配

场景：聚水潭供应商地址更新后

操作：点"重新匹配" → 确认 → 清除所有失败标签 → cron自动用最新地址重试

适用：未匹配 + 退货失败的记录

优先级方式

优先级方式

八、显示规则

  • 所有状态显示🏪供应商名称
  • 所有状态显示来源标签（🔵1688 / 🟡非1688）
  • 退货已下单显示内部单号（✅ 8370xxx）
  • 搜索框支持：采购单号 + 聚水潭内部单号

九、关键规则

  • 备注不能用换行符（用分号分隔）
  • 同供应商合并为一个退货订单
  • "完成"逻辑：1688退款成功 或 非1688退货已下单（1688退款中有退货单号≠完成）
  • 退货订单推送到 shopId=21571486（外贸采购退货）
  • 历史数据永久保留
