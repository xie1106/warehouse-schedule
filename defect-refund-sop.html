三、1688采购单 — 退款+退货流程

操作步骤

  1. 仓库扫码登记次品 → 拍照上传
  2. 点一键退货 → 弹窗按供应商分组 → 确认
  3. 系统同时做两件事：
    • 创建聚水潭采购退货订单（同供应商合并，即时回写内部单号）
    • 打开1688后台退货页面
  4. 在1688后台提交退款申请（带图片凭证）
  5. 等卖家同意 → 填写快递单号（买家退货）
  6. 在聚水潭退货订单打面单发货寄回
  7. 1688状态变为"退款中"（系统显示"卖家收货"）→ 卖家确认收货 → 退款完成
⚠️ 两条线并行：聚水潭退货单（打面单发货）+ 1688退款（拿回货款），缺一不可。

状态流转

待处理 → 等待卖家同意 → 等待买家退货(填快递单号) → 等待卖家收货(1688"退款中") → 退款完成 ↓ 卖家拒绝申请/卖家拒绝退款(异常)

各节点时间

节点时间
一键退货 → 聚水潭订单创建即时（点击后立即创建）
同步1688后台退款状态每2小时自动同步
等待卖家同意1-3天
买家退货（填快递单号+寄回）打面单后1-3天
卖家收货(1688退款中) → 退款完成卖家确认后即时

四、非1688采购单 — 退货流程

操作步骤

  1. 仓库扫码登记次品 → 拍照上传
  2. 点一键退货 → 弹窗按供应商分组 → 确认
  3. 系统自动创建聚水潭采购退货订单（~2分钟）
  4. 去聚水潭"外贸采购退货"店铺打面单发货

状态流转

待处理 → ⏳创建中 → ✅已下单(内部单号) = 完成 ↓ ↓ 未匹配 退货失败

五、一键退货

  1. 点"一键退货"按钮
  2. 弹窗列出待退货记录，按供应商分组（仅显示供应商名+数量）
  3. 🔵1688 / 🟡非1688 标签区分来源
  4. 勾选确认 → 提交
  5. 系统即时：按供应商合并 → 创建聚水潭退货订单 → 回写内部单号

范围：所有未建聚水潭退货单的记录（含1688退款中但未建单的）

⚠️ 退货单只能通过前端"一键退货"按钮创建，不会自动创建。

六、重新匹配

场景：供应商地址更新后，或新SKU需要映射

操作：点"重新匹配" → 确认 → 清除失败标签，更新供应商映射

注意：重新匹配不会自动创建退货单，匹配成功后需手动点"一键退货"

适用：未匹配 + 退货失败的记录

八、显示规则

  • 商品编码显示为：款号 · 颜色 · 尺码 ×数量（如 E6696 · 蓝色 · M ×1）
  • 多款之间用红色竖线 | 分隔
  • 所有状态显示🏪供应商名称
  • 所有状态显示来源标签（🔵1688 / 🟡非1688）
  • 退货已下单显示内部单号（✅ 8370xxx）
  • 1688退款状态badge旁显示退货订单号（📦8370xxx）
  • 搜索框支持：采购单号 + 聚水潭内部单号（搜索时忽略tab过滤）

记录合并规则

合并（同一组显示）不合并（独立显示）
同采购单号 + 都是待处理（无退款、无退货标签）同采购单号但不同退货订单号
同采购单号 + 同退货订单号同采购单号但状态不同（一个已退货一个待处理）
同采购单号 + 同退款状态（卖家同意/买家退货/卖家收货/完成）status=done 或 error（无退款标签的）
💡 所有状态（包括卖家同意、买家退货、卖家收货、完成）都能看到图片和SKU明细。

九、关键规则

  • 备注不能用换行符（用分号分隔）
  • 同供应商合并为一个退货订单
  • "完成"逻辑：1688退款成功 或 非1688退货已下单且聚水潭订单未取消
  • 退货订单推送到 shopId=21571486（外贸采购退货）
  • 历史数据永久保留

任务频率说明
