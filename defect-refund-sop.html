次品退货 SOP（详细操作手册）

捷展贸易 · 最后更新：2026-09-10

📌 一句话流程：登记次品（拍照+采购单号）→ 系统自动匹配供应商/退货地址 → 点【🖨️ 面单】直接打印圆通电子面单 → 打包寄回 → 1688 采购单再点【🔗 1688后台】人工申请退款并填快递单号 → 卖家收货 → 退款完成。
重要：本系统不再通过「退货按钮/聚水潭API」创建退货单，面单直接打印。

二、快速上手（3 步）

  1. 登记：扫描/输入采购单号 → 输入次品明细（如 Y6661黑色M×1 或 E669622XL×2）→ 拍照上传 → 保存。
  2. 看状态：系统自动匹配颜色/码数、供应商、退货地址，记录显示「待处理」；若缺要素会标注「未匹配：缺XX」。
  3. 打面单寄回：点【🖨️ 面单】打印圆通电子面单 → 打包寄回；1688 单再点【🔗 1688后台】申请退款并填快递单号。
⚠️ 系统不会自动创建任何聚水潭退货单，也不再需要"退货"按钮；打印面单就是发货动作。

五、记录合并与展示规则

合并显示（同一张卡片）

  • 只有：相同采购单号 + 状态为待处理（无退货、无退款标签）的记录才合并。

独立显示（一张卡片一条记录）

  • 有退货标签 / 有退款标签 / 已处理完成的记录，全部独立显示，不合并。
  • 即：同采购单号下，只要状态不是待处理，每条记录单独一张卡片。

商品明细展示

  • 格式：款号 · 颜色 · 尺码 ×数量，多款之间用红色竖线 | 分隔。
  • 颜色/尺码来自聚水潭商品资料（自动匹配）。
  • 卡片显示 🏪 供应商名称；🔵1688 / 🟡非1688 来源标签。
  • 搜索框支持：采购单号 + 快递单号 + 备注内容。

六、1688 采购单 — 完整流程

操作步骤

  1. 登记：扫码登记次品 → 拍照上传（登记时带 1688 平台订单号）。
  2. 系统自动匹配颜色/码数、供应商、退货地址，显示「待处理」。
  3. 点【🖨️ 面单】：直接打印圆通电子面单。1688 采购单状态自动变为「等待同意」（橙色），非 1688 变为「完成」。
  4. 点【🔗 1688】：跳转到 1688 订单详情页，人工提交退款申请（带次品图片凭证）。
  5. 等卖家同意：系统每天凌晨自动从聚水潭采购单 labels 同步 1688 退款进度（退款成功/等待买家退货/等待卖家收货/退款关闭等），记录自动显示对应徽章，无需人工维护。
  6. 填快递单号：卖家同意后 1688 显示「等待买家退货」，把面单上的快递单号填进 1688 退款申请。
  7. 用打印好的面单打包寄回。
  8. 卖家收货 → 退款完成。
登记次品 → 待处理(自动匹配) → 🖨️打面单(状态变等待同意) → 🔗1688提交退款申请(带图) → 等待卖家同意 → 填快递单号(等待买家退货) → 寄回 → 等待卖家收货 → 退款完成 ↓ 退款被拒/关闭 → 异常（人工跟进重新申请） 取消面单 → 状态回到待处理（可重新打印）
⚠️ 退款申请与图片凭证必须人工在 1688 后台操作（图片无法自动搬运到 1688）。

七、非 1688 采购单 — 完整流程

操作步骤

  1. 登记：扫码登记次品 → 拍照上传。
  2. 系统自动匹配商品颜色/码数、供应商、退货地址（来自聚水潭资料，每天凌晨自动更新），显示「待处理」。
  3. 点【🖨️ 面单】→ 直接生成并打印圆通电子面单。
  4. 打包寄回供应商（面单收件地址=供应商退货地址）。
  5. 流程结束。
登记次品 → 待处理(自动匹配) → 🖨️打面单 → 寄回 → 完成 ↓ 未匹配(缺供应商/地址/颜色/码数 → 按原因处理)
💡 非 1688 不走 1688 退款流程；打印面单寄回即完成。如面单打印失败会标记「❌ 面单异常」。

八、面单打印（🖨️ 面单）

  • 按钮出现条件：该采购单已匹配到有效供应商 + 退货地址（待处理状态）。
  • 点击后：系统调用圆通电子面单 API（yto-proxy）实时生成面单，显示快递单号（YT 开头）。使用的圆通月结账号：K200416574（客户编码与客户ID一致）。
  • 面单版式：聚水潭同款（收件信息自适应换行；寄件：谢焕君 13316255984 广东省广州市番禺区大石街道会江鸿盛三路9号高昇产业园A301；含三段码/大单号/左右快递单号/明细区）。
  • 打印成功后自动写入 [面单:已打印:运单号]，卡片显示绿色「✅ 已打印 YTxxxx」徽章（刷新不丢失）。1688 采购单状态自动变为「等待同意」。
  • 失败自动写入 [面单:异常:原因] 并显示「❌ 面单异常」。
  • 点击「取消」按钮可取消面单，状态回到待处理，可重新打印。
  • 重新点击已打印按钮会重新生成一张新面单（新运单号），如需打印同一张请勿重复点击。
  • 打印后把快递单号填到 1688 退款申请（1688 单）。
  • 按供应商合并打印（工具栏「合并打印」）：同一供应商的所有待处理采购单合并为一张面单（一个快递单号、一次运费），1688 与非 1688 不合并（分组时按供应商+来源拆分，各生成各的）。勾选后批量生成；不创建聚水潭单。结果列表可逐张查看/打印。
  • 打印后把快递单号填到 1688 退款申请（1688 单）。
⚠️ 缺退货地址的采购单无法打印面单（未匹配：缺退货地址），需先补供应商退货地址。

九、未匹配原因与处理

判定规则：只有「缺供应商」和「缺退货地址」才算未匹配。缺商品资料/颜色/码数不影响退货操作。

未匹配原因含义处理办法
缺供应商未匹配到供应商（含供应商带 * 号/市场）等聚水潭脱敏；或在聚水潭补充商品供应商资料（同步后自动匹配）
缺退货地址有供应商但无退货地址在聚水潭供应商资料补地址（同步后生效），或联系管理员手工补

十、异常的定义与处理

异常类型判定处理
退款被拒退款状态 ∈ 退款关闭 / 卖家拒绝 / 卖家拒绝申请 / 卖家拒绝退款 / 申请失败去 1688 后台查看拒绝原因，重新申请或人工协商
快递单号获取异常记录带 [面单:异常:原因] 标签，显示「❌ 面单异常」稍后重试打印；仍失败联系管理员查圆通接口/地址完整性

十一、重新匹配（重匹配）

定义：对「未匹配」和「退货失败/异常」的记录，按最新映射（商品/供应商/退货地址，每天凌晨自动更新）重新评估。

适用对象处理内容
未匹配（缺供应商 / 缺退货地址 / 缺颜色 / 缺码数 / 缺商品资料）用最新映射补齐/纠正 [供应商] / [地址] / [明细] 标签
退货失败 / 退货异常（退款未完成）清除旧的 [退货:失败] / [退货:异常] / [退货:待处理] 标签，恢复可操作
  • 触发：顶部「重匹配」按钮（批量）。
  • 重新匹配不会创建任何退货单/退款单，也不改 1688/退款历史标签。
  • 匹配完整的记录回到「待处理」，可打面单；仍缺失的继续显示「未匹配：缺XX」。
  • 正常情况下页面刷新就会按最新映射自动计算；重匹配按钮用于手动立即清理旧失败/异常标签并刷新匹配标签。

1688退款状态同步机制

  • 脚本 sync_purchase_status.py 从Supabase获取所有po_id → 批量查聚水潭采购单API（每批≤20个）→ 提取labels字段中的退款状态
  • labels包含完整状态链：线上申请取消 → 等待卖家同意 → 等待买家退货 → 等待卖家收货 → 退款成功/退款关闭
  • 输出 purchase_status.json 推送到GitHub Pages，前端加载后显示对应TAB和徽章
⚠️ mapping数据（SKU/供应商/地址）100%从GitHub Pages JSON加载，不走Supabase（节省流量配额）。前端带 ?t=时间戳 防缓存。
