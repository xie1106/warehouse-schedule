🦐 次品退款 SOP

Standard Operating Procedure · 捷展贸易 · 次品图片收集系统 · 2026-08更新

一、系统概览

系统职责
次品图片收集系统收集次品图片 + 退款/退货状态追踪 + 一键退货下单
聚水潭ERP采购单管理、质检次品数量（权威来源）、退货订单推送
1688后台退款申请、退款状态（1688采购单专用）
💡 系统自动识别采购单类型：有1688平台订单号 → 1688流程；无平台订单号 → 非1688流程

二、1688采购单 — 退款流程

1
仓库登记次品
打开次品收集系统 → 扫码/输入采购单号 → 选SKU和数量 → 拍照上传 → 提交
2
确认退款数量
以聚水潭质检次品数（qc_defective_qty）为准，非收集系统登记数。
本次退款数 = 聚水潭质检次品数 − 已退款中/已退款数量
⚠️ 前提：前一条退款记录状态必须先从1688后台同步
3
提交1688退款
点击收集系统"📦退货"按钮 → 跳转聚水潭1688详情页 → 提交退款（带图片凭证）
• 一个采购单所有退货SKU合并为一个退款申请
• goodsStatus选 refundWaitBuyerReceive
4
状态追踪
系统定期同步1688退款状态，自动更新badge（退款中/已退款/退款关闭）

状态流转

正常流程：

未申请→ 等待卖家同意→ 等待买家退货→ 等待卖家收货→ 退款成功 ✅

异常：

卖家拒绝 / 退款关闭→ 需重新申请

三、非1688采购单 — 退货流程

1
仓库登记次品
同上，系统自动标记为"非1688"，并实时显示匹配到的供应商名称（🏪紫色标签）
2
编辑确认（可选）
点"✏️编辑" → 确认SKU和数量 → 可修改/删除 → 保存
3
一键退货
点"一键退货"按钮 → 弹窗按供应商分组显示 → 勾选确认 → 提交
系统自动处理：
① 通过聚水潭「商品多供应商API」实时查询真实供应商（排除吕**-整烫/市场）
② 从聚水潭「供应商列表API」获取退货地址（联系人、电话、地址）
③ 同一供应商的多个采购单合并为一个退货订单
④ 备注格式：每个采购单一行（采购单xxx | SKU明细 | 合计N件）
⑤ 推送到聚水潭"外贸采购退货"店铺
4
等待处理
提交后约2分钟内自动创建订单，badge从"⏳处理中"变为"✅ 订单号"
5
取消退货（如需）
已处理的订单可点"取消"按钮 → 记录恢复为待处理 → 聚水潭订单备注标记"取消"
6
打印面单发货
去聚水潭"外贸采购退货"店铺 → 找到订单 → 打面单 → 发货

Tab分类说明

Tab含义
非1688所有非1688采购单记录
待处理未提交退货请求的记录
已处理已创建退货订单的记录（可取消）
未匹配无法自动匹配供应商的记录，需人工确认
异常退货创建失败的记录（可重试）

状态流转

待处理→ ⏳ 处理中→ ✅ 已下单(单号)

取消：

✅ 已下单→ 取消 → 待处理

异常：

待处理→ ❌ 失败（无法匹配供应商）→ 🔄 重试
⚠️ "未匹配"处理：如果商品在聚水潭未填写供应商（或只有吕**-整烫），需要在聚水潭普通商品资料中补充真实供应商，系统下次会自动识别

供应商匹配逻辑详解

🔍 商品编码 → 供应商名称 → 退货地址，全流程自动完成

第一步：从次品记录提取商品编码（i_id）

例如：次品记录 "Y666134M×1" → 提取商品编码 "Y6661"

第二步：商品编码 → 供应商名称

优先级方式说明
1本地缓存映射已查过的商品编码自动缓存（131条），下次直接命中
2聚水潭「商品多供应商」API实时调用 /open/webapi/itemapi/suppliersku/getsupplierskulist，按i_id查询所有供应商，排除"吕**-整烫"和"市场"，取第一个有效供应商
3聚水潭采购单的supplier_id从采购单关联的供应商ID反查供应商列表

第三步：供应商名称 → 退货地址

优先级方式说明
1聚水潭「供应商列表」API实时调用 /open/supplier/query，按供应商名称模糊匹配（去掉"档口-"前缀），获取联系人、电话、地址（67个有地址）
2本地地址缓存从腾讯在线表格"市场货地址"tab同步的65个档口地址

完整匹配流程示例：

Y666134M×1→ i_id: Y6661→ 广州青木服饰有限公司→ 张生 / 138xxx / 广州市...

四、自动化机制

机制频率说明
非1688退货订单创建每2分钟检查待处理请求，按供应商合并创建聚水潭订单
供应商自动识别实时聚水潭商品多供应商API实时查询，自动缓存
退货地址获取实时聚水潭供应商列表API（67个有地址），本地备用
1688退款状态同步按需/手动触发从1688后台拉取退款进度更新badge
取消退货处理每2分钟处理取消请求，更新聚水潭订单备注为"取消"

五、关键规则

规则说明
退款数量来源聚水潭 qc_defective_qty，不以收集系统登记数为准
同SKU多批次不同批次独立追踪，不自动合并
供应商匹配优先级① 本地缓存映射 → ② 聚水潭商品多供应商API → ③ 采购单supplier_id
退货地址优先级① 聚水潭供应商列表(实时) → ② 本地地址缓存(在线表格)
无效供应商"吕**-整烫"、"市场"视为无效，自动跳过
同供应商合并同一供应商的多个采购单合并为一个退货订单
退货订单店铺推送到 shopId=21571486（外贸采购退货）
备注格式每个采购单一行：采购单xxx | SKU明细 | 合计N件
历史数据不自动删除，永久保留
✅ 总结：
• 1688采购单：登记 → 确认质检数 → 1688提交退款 → 系统追踪状态
• 非1688采购单：登记 → 一键退货（按供应商合并）→ 自动创建订单 → 打面单发货
• 供应商和地址全部从聚水潭API自动获取，无需手动维护
